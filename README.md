# Clash Merge

本地运行的 Clash / Mihomo 订阅合并器，提供中文配置界面和统一订阅 URL。可使用桌面版，也可作为 Node.js 服务或 Docker 容器运行。

## 桌面版

在 GitHub 仓库的 **Actions → Build desktop clients** 中手动运行工作流，或推送 `v1.0.2` 这类版本标签。构建完成后，从该次运行的 Artifacts 下载对应系统安装包。Windows 生成安装版与便携版，macOS 生成 DMG 与 ZIP，Linux 生成 AppImage。产物文件名包含应用名、版本、系统和架构。需要先将项目代码推送到 GitHub，Actions 才能运行。

桌面程序打开后自动启动本地服务；点击「停止服务」会关闭监听端口，停止页可再次启动。窗口顶部可修改端口，范围 1024～65535；更改后会重启服务，统一订阅地址随端口更新。端口与订阅数据保存在系统应用数据目录，关闭并重新打开程序后仍会保留。**端口改变后，需要在 Clash 客户端更新订阅地址。** 关闭桌面程序会停止服务。

桌面开发时可运行 `npm ci`、`npm run desktop`。跨平台安装包只通过 GitHub Actions 构建，不需要在本机打包。未签名的 Windows/macOS 安装包可能显示系统发布者提示；正式公开分发前应配置代码签名。

## Node.js 服务

需要 Node.js 22 或更高版本：

```sh
npm ci
npm start
```

打开 http://127.0.0.1:3838，添加 Clash YAML 订阅地址，点击「保存并更新」，再把「统一订阅地址」复制到本机 Clash 客户端。服务运行期间地址可用；关闭进程后不可访问。

也可使用 Docker Compose：

```sh
docker compose up -d --build
```

Compose 默认仅将 3838 端口发布到本机，并将配置和缓存保存到持久卷 `clash-data`。停止用 `docker compose down`；不要加 `-v`，否则会删除数据。

## 合并行为

- 按来源顺序合并节点、策略组、HTTP proxy-providers；名称添加「订阅名 · ID 前缀 /」以隔离同名项目。相同节点跨来源保留，不按服务器地址去重。
- 默认创建「订阅汇总」选择组，以 `MATCH,订阅汇总` 为统一出口。可在 Clash 客户端选择具体节点或上游策略组。
- 「沿用首个可用订阅」采用列表中首个成功获取或有旧缓存来源的规则及 rule-providers，重写规则中的策略组和 RULE-SET 引用。首个来源彻底不可用时会采用下一个来源，分流行为可能变化。
- 基础输出固定为 mixed-port 7890、allow-lan false、rule 模式、info 日志级别。不复制原始 DNS、TUN、控制器、监听端口或其他顶层设置；这些可由客户端自行配置。
- HTTP provider 地址保留，由 Clash 客户端请求。本服务仅缓存上游订阅 YAML，不代理 provider 下载。静态节点数不包括 provider 中的节点。
- 支持标准 Clash YAML；不支持 Base64 节点链接列表、单节点 URI、文件/inline provider 和 SUB-RULE 自定义子规则。包含客户端专用扩展的订阅需自行检查兼容性。

## 缓存与故障处理

- 默认缓存 60 分钟，支持 1～10080 分钟。后台每分钟检查一次，到期更新；客户端请求也会触发过期检查。
- 成功结果保存到本地；重启服务后可直接使用未过期缓存。
- 同一来源的同时请求共用一个上游请求，每批最多拉取 5 个来源。
- 上游超时、HTTP 错误或配置无效时保留最后一次成功内容。旧缓存可无限期兜底，界面会显示错误和缓存时间；应及时修复长期失败的来源。
- 失败后 60 秒内不自动重试，避免客户端反复请求导致上游压力；「刷新缓存」可立即重试。
- 没有旧缓存的失败来源暂时跳过；全部不可用时返回错误而非空配置。输出 YAML 注释和 HTTP `X-Clash-Merge-Skipped` / `X-Clash-Merge-Stale` 标头标示降级状态。
- 修改来源 URL 会使该来源缓存失效。单次请求超时 20 秒，响应上限 10 MB，最多 50 个来源。

## 数据与访问

默认数据位于 `data/config.json` 和 `data/cache/`。配置含原始订阅地址，缓存含节点凭据，请勿提交到 Git 或分享给他人。删除来源会清除对应缓存。备份整个 data 目录即可迁移。

默认只监听 `127.0.0.1`，管理界面没有登录功能，适合可信本机使用。订阅地址附带随机令牌。API 限制 Host 和跨站访问，但这不等同于用户身份认证。不要直接暴露到公网或不可信局域网。

环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| PORT | 3838 | HTTP 端口 |
| HOST | 127.0.0.1 | 监听地址 |
| DATA_DIR | 项目目录下 data | 数据目录 |
| ALLOWED_HOSTS | 无额外主机 | 额外允许的主机名/IP，以逗号分隔，不含端口 |

桌面版端口在窗口内设置，不使用上述 `PORT` 环境变量。

Docker 内 HOST 为 0.0.0.0，但 Compose 只向宿主机 127.0.0.1 发布端口。如需跨设备使用，应自行添加认证反向代理，并配置相应监听地址和 ALLOWED_HOSTS；客户端里的 127.0.0.1 始终代表客户端自身设备。

## 开发与验证

```sh
npm run dev
npm test
```

测试覆盖名称冲突、策略组/provider/规则引用、并发去重、持久缓存、过期与故障回退、来源变更、订阅令牌和跨站访问限制。

技术栈：Node.js 内置 HTTP 服务、yaml、原生 HTML/CSS/JavaScript，无数据库或前端构建步骤。
